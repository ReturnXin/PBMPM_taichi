# 水体和 PBMPM/XPBMPM 软体摇晃盒子

当前统一入口是仓库根目录的 `main.py`，与 `python -m rigid_coupling` 共用此模块。详细分项文档见 [毕业论文／实验优化](../../../毕业论文/实验优化/00_优化总览与使用方法.md)。

## XPBMPM 已接入主材料分支

```powershell
.\.venv\Scripts\python.exe main.py --scene shake_soft --arch cuda --elastic-solver xpbmpm --compliance 0.000001 --iterations 10
```

XPBMPM 默认使用前期章节的 legacy 旋转目标、每物理步 0.5 乘子衰减、积分后重力及 F 奇异值限制。`--elastic-model experiment` 使用原形状/体积混合目标、每步清零乘子和步首重力。PBMPM 默认保留 experiment 模型，使用 `--elastic-solver pbmpm` 对照；比较材料求解器时需显式选择相同模型。

局部更新为 `a=alpha/dt²`、`delta=(target-D-a*Lambda)/(w+a)`、`D+=w*delta`、`Lambda+=delta`，默认 w=1。乘子参与存档、复位和有限值检查；只有 XPBMPM 且含软体时分配，水体不增加这一字段。实现直接进入 Materials、Solver 和已有 CUDA 图，不依赖章节实验求解器。该移植支持软体/刚体场景，不解除 reflected 对软体混合场景的限制。验证命令为 `python -m validation.runtime --output results/new_check`。

## 水面凹陷的成对镜像传输试验

新增可选的墙面运动处理，适用于完整传输的水/刚体盒子：

```powershell
.\.venv\Scripts\python.exe -m rigid_coupling --scene shake_water --gui --arch cuda --boundary-density available --wall-transfer reflected
```

选择 `reflected` 时，CLI 默认采用 `available` 密度、`clamped` 密度反馈及 `fluid_relaxation=1`。原有启动命令仍使用 `clamp` 墙面截断及原来的参数。新模式暂不支持增量传输、软体或过薄的容器；直接构造 `Config` 时需显式设置相应参数。

新模式将真实粒子的运动权重分配给真实及墙面镜像样本，P2G 后在所有对应样本位置 G2P，再反射回真实粒子并按同样权重合并。墙面法向运动取奇延拓、切向运动取偶延拓；旋转和移动壁面使用相对壁面的运动。真实粒子数量不变，镜像样本不加入客观密度，接触修正仍使用完整的真实粒子质量。只在 P2G 中加镜像而不配对 G2P 的原型在长时测试中出现振荡，未作为正式实现保留。

`--density-feedback clamped` 使用目标 `J*=1/max(n/a,1)`，按 `0.1a` 融合；欠填充时目标回到 1，不将自由表面的空气支撑缺失解释为负压。`--density-feedback legacy` 可恢复原来的仅过密反馈。仅改变密度反馈未解决旧墙面处理的凹陷，新模式的效果来自配对传输及反馈的组合。

这属于本项目对 PBMPM 的实验扩展。当前仍有采样误差、有限迭代误差和浮力辅助的近似，不能视为精确的流体压力求解。复现数据、长时对照、体积估计与验证见 [物理修复报告](../results/density_consistency_20261102/report.md)。

2026-11-03 修复了初版 `reflected` 的运行性能回退：G2P 的墙面反力改为每粒子保存、每 128 个粒子分块求和、最后统一写入，消除所有水粒子竞争同一个向量的原子累加。配对镜像传输、密度反馈、粒子数、dt 和迭代次数保持原设置，没有新增每步粒子状态 CPU 回读。需要重启演示进程加载代码；[最新性能与验证记录](../results/reflected_performance_20261103/report.md) 包含按 GUI 每次推进 2 步的对照。旧报告在其他 GPU 应用高负载时测得的 +16–17% 不能代表空闲桌面下的相对开销。

RTX 5060 Ti、profiler 关闭、同状态轮换 7 批的实测中，每次推进 2 步时，固定盒子的求解耗时从 10.63 降至 6.59 ms/物理步（下降 38.0%），移动旋转盒子从 10.33 降至 6.15 ms/步（下降 40.5%）。12 项相关测试以及 CUDA 图/普通执行、鼠标施力释放重放均通过；这些是求解计时，不包含绘制，也不是 GUI FPS。

## 鼠标拖动增量驱动所有水粒子

水演示包含水层及 3 个轻质小刚体，默认固定盒子，直接用鼠标带动水；软体演示包含 3 个不同颜色的小软体和 3 个绿色小刚体，继续用鼠标摇晃盒子。两者共用运动边界、刚体碰撞、线框容器显示和 GIF 录制代码。

```powershell
Set-Location -LiteralPath 'D:\mine\learningMarkdown\科研知识库\code\PBMPM_taichi'
.\.venv\Scripts\python.exe -m rigid_coupling --scene shake_water --gui --arch cuda
.\.venv\Scripts\python.exe -m rigid_coupling --scene shake_soft --gui --arch cuda
```

运行其中一条即可。水场景中按住鼠标左键并拖动，向所有水粒子施加水平 X/Z 力，无需选择或抓取局部粒子。施力方向由相邻两次鼠标采样的增量 Δx、Δy 决定：往哪边拖就往哪边施力，拖得越多则输入越强，受加速度上限限制。只按下、按住不移动或松开时均不新增鼠标力，保留粒子已有速度。增量按当前相机的水平朝向映射：横向对应左右，纵向对应前后，竖直分量始终为零。水体继续按惯性、重力、压力和盒壁接触运动。右键调相机、暂停、自动摇晃、光标移出有效画面或进入控制栏时会取消鼠标输入并清除待处理增量。软体场景的左键仍移动、倾斜盒子。`A` 切换自动摇晃及鼠标控制，`Space` 暂停，`R` 复位，`Esc` 关闭。

容器仅绘制 12 条棱，去掉实心墙面的顶点、法线字段及逐帧更新，物理上仍保留六面封闭容器。自动摇晃和软体鼠标控制时，壁面的实际位置和朝向同时用于物理接触及线框绘制。水和软体的壁面接触均允许切向滑动，软体的默认摩擦系数为 0，软体和小刚体之间也不施加摩擦。刚体按整体形状处理盒壁接触，并进行小规模盒体间碰撞；软体接触后的位移和形变更新复用已有的质量加权修正传递。

鼠标拖动量直接控制水平加速度 `a_mouse = 350 * delta_horizontal`，大小上限为 15.75，当前力度较上一版再降低 30%。加速度幅值不随 dt 或本帧物理步数缩放，步数只控制本次加速度的作用时长；每个物理步在原 `Materials.predict` 中积分 `d += a_mouse * dt²`。PBMPM 保存的 d 是 `v * dt`，因此这对应 `v += a_mouse * dt`。已删除质心位置吸引、平均速度反馈和固定速度增量输入。没有物理步时先暂存拖动量，松开或暂停会清除暂存；普通路径和 CUDA 图共享剩余步数计数，输入用完后自动归零。所有水粒子使用相同的水平加速度，无新增粒子遍历、kernel 提交或粒子状态 CPU 回读，控制字段仍为 28 字节。小刚体通过原来的水体耦合运动。录制和非交互求解不分配鼠标字段，预测计算在编译时跳过鼠标分支。这是演示用外部控制，不属于 PBMPM 原文的材料约束；盒壁密度补偿和传输模式继续生效。

水的盒壁约束在网格回传前施加，使盒壁引起的压缩同时进入平移和仿射位移。随后保留几何裁剪，限制残余穿透；盒壁裁剪和小刚体接触产生的新增位移也通过独立的水材质修正网格重建压缩梯度，补入仿射位移 D。水保留接触后的精确平移位移，仿射修正取对称部分以保持压缩信息并避免重复施加冲量和引入额外自旋；软体继续使用原有的完整位移和仿射修正。这个粒子接触扩展遵循 PBMPM 原文通过网格协调候选形变的原则，原文没有给出这一扩展的具体公式。初始水块铺满较大的盒底后，水位仍会正常下降；粒子数量和静止体积保持不变。前后对照见 `results/shake_box_20261030/water_affine_fix/report.md`。

默认水场景将小刚体和盒壁的接触增量合并，每轮只传递一次修正；节点质量复用本轮 P2G，零接触阶段在设备端跳过修正循环。水与软体混合时保留分离的修正通道。

水演示现在默认试用 `raw`：外盒墙体不增加填充密度，仅按真实水粒子及小刚体样本的静止体积 V0 估算。P2G 在网格上累加 `q_i = sum(w_ip * V0_p) / h³`，G2P 将网格填充率插值回水粒子，沿用原来的密度 → J 反馈及材料 D 求解。这里使用静止体积 V0，压缩后的粒子聚集仍能表现为较高填充率。完整传输每轮重建密度；增量传输在冻结几何下复用第一轮密度。该模式不分配额外墙体占据率缓存。外盒物理接触、刚体体积贡献、鼠标水平加速度和线框显示继续使用原设置。

正常启动水演示即可试用 raw，需要重启演示进程生效。`--boundary-density solid` 对照固定墙体填充密度 1，`--boundary-density mirror` 对照墙面镜像。软体仍默认 raw。之前同一平水层三秒对照中，raw 的区域高差为 0.000529，solid 为 0.008093；raw 的平均离底高度较低（0.052222 对 0.058879），底部 0.01 粒子比例也较高（13.85% 对 10.65%）。因此该切换是减少墙体密度反馈的试验，不能仅凭水面变平认定体积恢复已解决。[固定墙体密度及 raw 对照结果](../results/solid_wall_density_20261102/report.md)。

新增 `available` 试验模式，先估算墙体及刚体几何并集的占据率，以 `1 − 固体占据率` 得到可用体积；网格只累加真实水粒子的静止体积。G2P 用同一权重分别插值水贡献与可用体积，再计算两者的比值。固体重叠只算一次，不再叠加刚体样本密度；自由表面的可用空间仍包含空气，因此这是边界归一化的填充密度。分母过小时跳过密度反馈。

```powershell
.\.venv\Scripts\python.exe -m rigid_coupling --scene shake_water --gui --arch cuda --boundary-density available
```

外盒和刚体姿态固定时复用几何缓存，刚体任意倾斜时只在边界附近进行切片积分。grid32、三刚体新增约 256 KiB 字段，无每步粒子状态 CPU 回读。同进程预热计时中，相比 raw 的中位开销为固定几何约 +2.1%、浮体运动约 +5.9%、盒子和浮体一起运动约 +10.3%；这些数值包含整步求解且有批次波动。本轮三秒对照中，平水层的底部 0.01 粒子比例由 solid 的 10.65% 降至 available 的 9.88%，但区域高差由 0.008093 增至 0.008921；三浮体高差由 0.005968 增至 0.010915。因而保持显式开关、默认 raw，尚不能认定凹陷已修复。[可用体积归一化报告](../results/available_density_20261102/report.md)。该模式也支持 `--transfer-mode incremental`。

后续 available 的密度对 J 的融合力度改为 `0.1a`，其中 a 是插值回粒子的可用体积比例；密度仍为水贡献除以 a，目标仍为 1。靠边界时减弱反馈，完整可用空间保持原力度，只增加已有 G2P 内的标量计算。上段计时和效果记录的是固定 `0.1` 权重的旧版。[反馈衰减及新对照](../results/available_feedback_20261102/report.md)。

`solid` 对照根据二次 B 样条支撑域的固体占据比例补墙体密度，边角采用盒内积分的补集，盒内空气保持为空域。轴对齐时解析积分，绕 Z 旋转时切片积分；静止盒子复用几何缓存，grid32 新增约 128 KiB 字段。此前实测静止完整路径中位数为 7.14 ms/步，移动旋转为 8.94 ms/步，批次波动较大。这是 solid 的历史计时，不代表当前 raw 的性能。

之前的 mirror 方法将真实水粒子跨六面反射，仅散射客观填充密度，自由表面不反射。该路径帮助恢复厚度，但侧壁反馈与位移约束还会产生额外水面弯曲，因而保留为对照。[镜像实现与性能报告](../results/shake_box_20261030/mirrored_boundary/report.md)、[静置凹陷消融](../results/static_wall_ablation_20261102/report.md)。

水场景可以试用增量传输：

```powershell
.\.venv\Scripts\python.exe -m rigid_coupling --scene shake_water --gui --arch cuda --transfer-mode incremental
```

第一轮仍做完整 P2G/G2P，后续轮次保留网格候选位移，只加入相对上次 G2P 的材料和接触增量；每轮仍更新 d、D 和客观填充密度，压力迭代次数不变。它要求内迭代期间粒子位置冻结及水/刚体分离网格，目前不支持软体。PBMPM 原文每轮做完整传输，增量模式是本项目的实验扩展。

grid32、5 轮、5176 个水粒子的冻结 4dx 剪切试验中，5 轮 APIC 能量保持从 40.5% 提高到 81.5%。在尚未修正盒壁密度的基线实验中，增量传输未改善底部聚集，静置和摇晃的底部比例反而更高；预热 CUDA 图计时约为完整路径 7.59 ms/步、增量路径 8.00 ms/步，单批计时有波动；新增字段约占 0.62 MiB。完整传输仍为默认，增量路径保持显式开关。该基线结果与 PBMPM 原文的比较见 [增量传输实验报告](../results/shake_box_20261030/incremental_transfer/report.md)，当前镜像盒壁处理的结果见上面的新报告。

水场景的小刚体密度为水的 0.35 倍，默认开启的浮力辅助仅用于底部脱困：按旋转后形状检查盒底间隙，且实际密度小于水、估计有浸没时，才补足缺失的向上速度增量。离底的刚体保持正常耦合响应；已有接触提供足够向上运动时也不重复补力。辅助仍使用平均水位，是展示近似，可用 `--no-buoyancy-assist` 完全关闭。具体条件与验证见 [底部浮力辅助](../../../毕业论文/实验优化/13_底部触发浮力辅助.md)。水粒子的绘制半径为原摇晃演示的 55%，只影响显示。软体场景默认弹性修正强度 0.04，小刚体密度为 0.7。
